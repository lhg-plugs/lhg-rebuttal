# lhg-rb-diff：修改对照表规范

## 何时使用

- 逐条回应写完后，需要生成编辑/审稿人一眼看清"改了哪"的对照表时。
- 投稿前检查"对照表行数=意见条数、每行状态明确"时。
- 修改稿页码大改后，需要同步更新对照表位置标注时。

不适用：审稿意见少于 3 条且全是格式问题——在回信正文里顺带说明即可，不必单独成表。

## 输入与输出

**输入**：意见清单（lhg-rb-parse 输出）+ 逐条回应（含修改位置）。

**输出**：修改对照表（Markdown 表格）+ 完整性自查结论。

## 分步方法论

### 第 1 步：五列标准

对照表固定五列，不许增删：

| 列 | 写什么 | 示例 |
|---|---|---|
| 意见编号 | E1 / R1-C1 | R1-C1 |
| 审稿意见 | 原话摘录（一句话版） | The sample size (n=50) is too small. |
| 回应摘要 | 一句话：改了什么 / 为什么没改 | 已补实验 n=120，结论不变 |
| 修改位置 | 页码+行号，或图表编号 | p. 3, lines 45-60, Figure 4 |
| 状态 | 已修改 / 部分修改 / 未修改（已解释） | 已修改 |

"修改位置"不许写"见正文""已修改"——编辑要的是能直接翻到的坐标。

### 第 2 步：行列完整性

- **行数 = 意见条数**：意见清单有 8 条，对照表必须 8 行，多一行少一行都是事故。
- **编号一一对应**：对照表的编号集合 = 意见清单的编号集合，diff 一下，差一个都不行。
- **状态列无空**：每行状态三选一，不许空着。"未修改"必须配解释——"未修改（已解释）"，光写"未修改"等于挑衅。

### 第 3 步：状态的诚实写法

- **已修改**：改了，且修改位置真实。写完对照表后，随机抽 3 行去修改稿里核对页码行号——这是最容易穿帮的地方。
- **部分修改**：改了一半，另一半在回应里解释了。摘要里写清"哪部分改了、哪部分没改"。
- **未修改（已解释）**：没改，但回应里有充分解释+证据。摘要写"未修改，理由见回应 R1-C3"，不许只写"未修改"。

### 第 4 步：位置标注规范

- 页码行号以**修改稿**为准，不是原稿——返修后页码会变，对照表必须跟着改。
- 格式统一："p. 3, lines 45-60" / "Figure 4" / "Table 1" / "Section 2.3"。
- 图表编号变化时（如新增 Figure 4 导致原 Figure 4 变 Figure 5），全文统一更新，对照表不能写旧编号。

### 第 5 步：对照表自查清单

- [ ] 五列齐全，列名标准
- [ ] 行数 = 意见条数，编号集合 diff 无差异
- [ ] 每行状态三选一，无空值；"未修改"都带了"已解释"
- [ ] 修改位置具体到页码行号/图表编号，无"见正文"
- [ ] 位置标注与修改稿实际位置一致（抽查 3 行）
- [ ] 图表编号与修改稿一致（无旧编号残留）

## 完整示例

| 意见编号 | 审稿意见 | 回应摘要 | 修改位置 | 状态 |
|---|---|---|---|---|
| E1 | Please shorten the manuscript to 8 pages. | 12 页→8 页，删减了第 2 节背景综述 | 全文 | 已修改 |
| R1-C1 | The sample size (n=50) is too small. | 已补实验 n=50→120，结论不变 | p. 3, lines 45-60, Figure 4 | 已修改 |
| R1-C2 | Figure 3 lacks error bars. | 已补误差棒 | p. 5, Figure 3 | 已修改 |
| R2-C1 | Hyperparameters not specified. | 方法部分已补充 | p. 2, Table 1 | 已修改 |
| R2-C2 | Contradiction with Smith et al. (2024) not discussed. | 讨论部分增加对比；实验条件不同，详见回应 | p. 8 | 部分修改 |
| R3-C1 | Suggest redoing with XX method. | 超出本研究 scope，已补方法适用性讨论，列为未来工作 | p. 9 | 未修改（已解释） |

自查：6 条意见 6 行，编号集合一致；状态列：已修改×4、部分修改×1、未修改（已解释）×1；位置均为修改稿坐标。

## 反模式

- **位置写"见正文"**：编辑没时间全文找你的修改——写具体坐标。
- **行数对不上**：意见 8 条表只有 7 行——漏的那条就是拒稿的理由。
- **状态注水**：明明没改写"已修改"——编辑抽查发现，信任直接清零。
- **原稿页码**：返修后页码变了，对照表还是原稿页码——每次改完修改稿，同步更新对照表。
- **摘要=回应复制**：摘要是"一句话"，不是把整段回应粘进来——超过 50 字的摘要重写。

## 对照表与回信正文的衔接

对照表不是孤立文档，它和回信正文、修改稿是"三位一体"：

1. **回信正文**：详细版，每条回应含引用、策略、证据、位置。给审稿人看推理过程。
2. **对照表**：摘要版，一行一条，给编辑快速核对"改了哪"。
3. **修改稿**：用修订模式（track changes）或高亮标出所有修改，位置与对照表一致。

三处编号统一（R1-C1），三处位置一致（p. 3, lines 45-60）。投稿前做"三角核对"：随机抽 3 条意见，从对照表→回信正文→修改稿走一遍，任何一处对不上都打回。

Cover letter 里提一句："A summary of changes is provided in the table below, and all revisions are highlighted in the revised manuscript."让编辑知道去哪看。

## 修订模式使用规范

- 用 Word 的 track changes 或 LaTeX 的 latexdiff，保持修改痕迹可见。
- 不要"接受所有修订"后提交干净版——审稿人要看的是"你改了什么"，不是"改完长什么样"。
- 新增图表用红色框标出，并在对照表里写新编号。
- 对照表行数=意见条数：多一行少一行都是事故。
- "修改位置"不许写"见正文""已修改"，要的是能直接翻到的坐标。
- 页码行号以修改稿为准：返修后页码会变，对照表必须跟着改。
- 随机抽 3 行去修改稿里核对位置——这是最容易穿帮的地方。
- Cover letter 里告诉编辑去哪看对照表和修订痕迹。
- 对照表是给编辑看的摘要，回信正文是给审稿人看的推理过程，两者都要有。

## 一句话速查

- 五列：意见编号 / 审稿意见 / 回应摘要 / 修改位置 / 状态，不许增删。
- 行数=意见条数，编号集合 diff 零差异。
- 状态三选一：已修改 / 部分修改 / 未修改（已解释），"未修改"不带解释=挑衅。
- 位置以修改稿为准，具体到页码行号，抽查 3 行核对。
- 图表新增导致编号顺延时，全文统一更新。
- 摘要超 50 字重写；"未修改"不带解释=挑衅。
- 投稿前做"三角核对"：对照表→回信正文→修改稿随机抽 3 条走一遍。
- 修订痕迹保持可见：不要"接受所有修订"后提交干净版。
- 新增图表用红色框标出，并在对照表里写新编号。
- 对照表行数=意见条数：多一行少一行都是事故。
- "修改位置"不许写"见正文""已修改"，要的是能直接翻到的坐标。

## 自检与反馈

**质检门**（输出前自查）：

- [ ] 五列齐全，列名标准，无多余列
- [ ] 行数 = 意见条数，编号集合与意见清单 diff 无差异
- [ ] 状态列无空值，"未修改"都带了"（已解释）"
- [ ] 修改位置具体（页码行号/图表编号），无"见正文"
- [ ] 抽查 3 行位置标注与修改稿一致

**标准冒烟用例**：输入 4 条意见的回应（含 1 条未修改但已解释），应输出 5 列 4 行对照表，行数=4，状态列含"未修改（已解释）"且摘要注明理由指向，位置均为修改稿坐标。

**一键反馈**：发现方法论缺口，以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-rebuttal/issues，正文写清"场景 → 当前方法的不足 → 期望补充什么"。
